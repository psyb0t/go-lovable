# go-lovable

Unofficial Go client for the Lovable API, generated from the OpenAPI document Lovable publishes. If you only want to use the client from an agent, read [.agents/skills/go-lovable/SKILL.md](.agents/skills/go-lovable/SKILL.md) instead; this file is about changing the code.

## Architecture

One generated package, `lovable`, at the module root, driven by `gen.go`:

`scripts/fetch-spec.sh` downloads `https://api.lovable.dev/v1/openapi.yaml` to `api/openapi.yaml` → `scripts/fix-nullable-types.sh` writes `api/openapi.fixed.yaml`, through the local YAML-aware `go tool patch-spec`, converting nullable type lists, null enum entries and schema example arrays into OpenAPI 3.0.3 form → oapi-codegen with `config.yaml` → `client.gen.go`.

## Stack

- Go 1.26.10.
- oapi-codegen, pinned as a `tool` dependency in `go.mod`.
- Runtime: `github.com/oapi-codegen/runtime` and `github.com/oapi-codegen/nullable`.
- The patch tool uses `gopkg.in/yaml.v3` and `ctxerrors`.

## Layout

- `gen.go`, `config.yaml`, `client.gen.go`: the package.
- `client_test.go`, `example_test.go`: tests, including the README example.
- `scripts/`: spec download, the patch wrapper, lint and security scans.
- `internal/cmd/patch-spec/`: YAML conversion and its unit tests.
- `api/`: the downloaded spec, gitignored.
- `vendor/`: committed, regenerated by `make dep`.

## Dev workflow

Everything runs in the `Dockerfile.dev` image. You need Docker and Make.

```bash
make dep       # go mod tidy + go mod vendor
make generate  # download the spec and regenerate
make lint      # shellcheck, shfmt, go fix, golangci-lint
make test      # go test -race
make sec       # gitleaks, govulncheck, semgrep
```

## Project-specific landmines

- The spec is OpenAPI 3.1.0. Keep the patch before generation. Unsupported type unions fail instead of being guessed.
- The patch also uses directory terminology in generated descriptions, matching the repository wording rules.
- Null enum entries otherwise become `"<nil>"` string constants. Remove those entries while keeping the schema nullable.
- Keep `nullable-type: true` so required nullable fields preserve JSON null. Read `nullable.Nullable[T]` with `IsNull()` and `Get()`.
- Keep the `number` to `float64` mapping for numeric metrics and credit amounts.
- The base URL is `https://api.lovable.dev`; generated paths already contain `/v1`.
- Auth is the `Lovable-API-Key` header or a bearer token. Keys belong to one workspace and require operation-specific scopes. Tests use `httptest` only.
- `ListProjects` requires a workspace ID slice. Pagination uses `Pagination.HasMore` and a nullable opaque `Pagination.NextCursor`. No automatic pagination or retry is provided.
- Publishing returns 202. Poll deployment status with backoff and a bounded timeout. A response timeout does not prove a mutation was rolled back.
- Source archives have no Git history. The security script reports that fact and still scans the whole worktree.
- `make generate` always downloads the current spec, so it can change the client even when nothing here changed. Review the generated diff before committing it.
- `.github/workflows/regen.yml` regenerates the client every day and releases the result. When the checks fail, Claude edits the repository to fix them, but a fix may not touch the paths listed under `fix_protected_paths` in that workflow: the workflows, the Makefile, `AGENTS.md`, `.agents/rules/`, the lint, security and spec download scripts and their configs. A problem that needs a change there fails the run and needs a manual fix.
